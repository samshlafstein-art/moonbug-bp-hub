# Report Style Guide

Visual and structural conventions for any polished report, deck, or page
this skill generates (an HTML page, a Markdown doc meant to be read as a
document, or a slide artifact) — not for ordinary chat answers, which stay
conversational.

Structure borrowed from an internal reference (a McKinsey-style exec
report): a bold display headline paired with a clean sans-serif body, a
numbered "Exhibit" callout with a bolded one-sentence takeaway placed
*above* every chart (never below), full-bleed color-block pages for a
single pull-quote insight, and a disciplined 2–3 color chart palette. Do
not reuse McKinsey's own navy/blue identity — this reskins that structure
with a different palette and a rounder, warmer type pairing suited to
Moonbug's kids-content brand.

## Palette

CoComelon-inspired (an approximation of the show's cheerful primary
colors — not an official brand hex sheet, since one isn't public):

| Role | Color | Hex |
|---|---|---|
| Primary / headlines, key numbers | Sunshine Yellow | `#FFC72C` |
| Secondary / links, chart series 1 | Sky Blue | `#3AB6E8` |
| Accent / alerts, chart series 2 | Coral Red | `#F0523A` |
| Accent / positive trend, chart series 3 | Leaf Green | `#5FB865` |
| Text, headers on light backgrounds | Charcoal Navy | `#1E2A45` |
| Page background | Warm Cream | `#FFFDF6` |
| Full-bleed pull-quote background | Charcoal Navy | `#1E2A45` (text in white/yellow on this) |

Use yellow and navy as the dominant pairing (like the McKinsey deck's blue
+ white); reserve red and green for genuine signal — red for
under-delivery/risk, green for over-performance/lift — never decoratively.
Never use more than 3 chart colors on one chart.

## Typography

- **Display/headline font**: a rounded, friendly serif or slab serif (e.g.
  Fraunces, Lora, or a similar warm serif) — echoes the McKinsey deck's
  serif display headlines but rounder and less corporate, fitting a kids'
  media brand's parent-facing materials.
- **Body/data font**: a clean geometric sans-serif (e.g. Inter, or a
  similar humanist sans) for body copy, tables, and chart labels.
- Don't use more than these two families. Headlines are large and bold;
  body text stays small and restrained so the numbers carry the weight.

## Structural conventions

1. **Exhibit numbering**: every chart gets an "Exhibit N" label plus a
   **bolded one-sentence takeaway** directly above it — not a generic
   chart title. E.g. "Exhibit 2 — **FAST channel delivery consistently
   underperforms YouTube and CTV by 15 points.**" The sentence should
   state the finding, not just describe the axes.
2. **Pull-quote pages**: for the single most important insight in a
   report, give it its own full-bleed Charcoal Navy panel with one large
   sentence in white/yellow — mirrors the reference deck's isolated
   insight pages. Use sparingly (one per report, for the headline
   finding only).
3. **Grid**: generous whitespace, left-aligned body text, short line
   lengths. A 2-3 column grid for supporting text next to a chart, similar
   to the reference deck's column layout.
4. **Charts**: simple bar/line/bubble charts only — no 3D, no excessive
   gridlines, direct data labels over legends where there are 3 or fewer
   series. Circles/bubbles work well for comparing a handful of named
   items (channels, categories) by size, echoing the reference deck's
   bubble-chart exhibit style.
5. **Footer**: small, consistent — source line ("Source: Moonbug Brand
   Partnerships Data Hub, synthetic data" or "...real YouTube Data API
   pull") and date, bottom of each page/section.

## When to apply this

Use this style guide when the person asks for a **report, recap, or deck**
as a deliverable (something to save, present, or send) — build it as a
published HTML artifact or a designed document. For an ordinary
conversational question in chat, answer in plain prose with inline charts
as usual; don't apply this heavier styling to every single answer.
